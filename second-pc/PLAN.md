# 두번째 PC — 개발 계획 (5일, PRD 1단계 마무리)

> 기준: PRD.md 7장 "1단계 — AI 없이 만드는 버전", 현재 `second-pc/` 폴더의 시안
> 원칙: "미정" 항목은 임의로 채우지 않고, 팀이 정할 때까지 빈칸 표시를 유지합니다.

## 1. 지금 상태 (확인한 것)

| PRD 1단계 기능 | 상태 | 근거 |
|---|---|---|
| 소개 웹페이지 (6장 화면 전체) | 시안 완료 | `index.html` |
| 기업·비영리단체 신청 | 폼은 있음, **저장은 안 됨**(입력 확인만) | `apply.html`, `main.js` |
| 소식·공지·캠페인 게시 | 글을 `content.js`에서 직접 고쳐 씀 | `content.js` |
| ESG 나눔 리포트 | 없음 | 링크만 있음 |
| 운영 원칙·후원금 사용 내역 | 없음 | 링크만 있음 |
| 이용약관·개인정보처리방침 | 없음 | 링크만 있음 |
| 기업·단체 연결 | 운영팀이 사람이 처리 (화면 불필요) | PRD 7장 |
| 인터넷 공개(배포) | 안 됨, 내 컴퓨터에서만 보임 | `README.md` |

## 2. 먼저 팀이 정해야 하는 것 (코딩 전에)

개발이 막히지 않도록 1일차 안에 정합니다.

1. 신청서 저장 방식: 구글 폼 연결 / 이메일 전송 / 구글 시트 (가장 쉬운 것부터 권장)
2. 신청서에 받을 항목 (기업: PC 대수·종류·수거 지역 등, 단체: 필요 대수·사양 등)
3. 개인정보 수집 동의 문구 (신청서에 꼭 필요)
4. 후원금 구조 (`[금액] 미정`)
5. 개인 PC 수요자·폐기 희망자를 이번 범위에 넣을지

나머지 미정 항목(성공 기준 수치, 후기, 파트너 로고, 사업자 정보, 데이터 삭제 방법, 해외 기증)은 "준비 중"으로 두고 배포합니다.

## 3. 일정

| 일차 | 할 일 | 끝났다는 기준 |
|---|---|---|
| 1일 | 위 5가지 결정, 디자인 시스템과 현재 `style.css` 색·글꼴 맞추기 | 결정 내용이 이 문서에 적혀 있고, 색·글꼴이 디자인 시스템과 같다 |
| 2일 | 신청서 연결: 항목 확정, 동의 체크칸, 저장 방식 연결 | 신청서를 제출하면 팀이 내용을 받아볼 수 있다 |
| 3일 | 새 페이지 4개: 운영 원칙·후원금 사용 내역, ESG 나눔 리포트, 이용약관, 개인정보처리방침 (내용은 팀이 작성, 모르는 수치는 "준비 중") | 푸터와 카드의 링크를 눌러 각 페이지로 이동한다 |
| 4일 | 휴대폰 화면 점검, 문구·오타 점검, 소식·공지 실제 글로 교체 | 휴대폰 너비(375px)에서 가로 스크롤과 깨짐이 없다 |
| 5일 | 인터넷 공개(배포), 인스타그램 홍보 문구 정리, 팀 최종 확인 | 공개 주소로 접속해 신청서 제출까지 해 본다 |

## 4. 위험한 부분

- 신청서는 연락처 등 개인정보를 받습니다. 동의 문구와 개인정보처리방침 없이 공개하지 않습니다.
- 데이터 삭제 증명서는 약속하는 문구이므로, 실제 방법이 정해지기 전까지 "준비 중"을 유지하거나 전문가 확인을 받습니다.
- 후원금 사용 내역은 실제 숫자가 없으면 지어내지 않고 빈 양식으로 둡니다.

## 5. 2단계(AI 기능)는 지금 하지 않습니다

PC 상태 평가, 자동 매칭, 리포트 자동 생성, 챗봇은 1단계에서 신청·나눔 기록이 쌓인 뒤에 정확해집니다. 5일 목표에서는 제외합니다.
